# 猫品种识别双路线项目设计

本项目对应《灵境后端二阶段考核任务》，沿用猫品种识别方向，独立实现代码、模型和记录。用户已委托自主选择方法，并允许在本机 RTX 5080 Laptop 16GB 显卡上运行；不修改第一阶段项目。

## 要完成的行为

上传一张猫图，两条路线处理相同原图，各输出一个品种。传统路线另展示定位框和分割轮廓；视觉语言模型另给简短的外观依据。界面并排显示结果和耗时，保存真实原始输出。默认关注照片中面积最大的猫；支持 Oxford-IIIT Pet 的12种猫品种。没有猫时展示明确状态，不生成品种分数。两条路线都可独立失败，保留原因。

## 参考与方案选择

- Grounded-SAM-2：借鉴检测框引导 SAM 分割的组合方式，不复制其演示项目。
- Candy-CY/Pytorch-garbage-classify：参考训练、验证选模及图片预测 API 的组织；不沿用其类别、Top-5 输出或旧路径。
- Salesforce LAVIS：阅读 BLIP2 的图像预处理与图像加问题生成示例。项目使用当前独立视觉语言模型接口，不为兼容旧框架安装整套历史依赖。
- 单用分类器不能展示第二阶段的检测、分割与图像问答；单用视觉大模型缺少同输入双路线对比。因此采用下面的两条路线，由开发者选择。

## 核心实现

传统路线：YOLO26 检测猫，取主要目标框；SAM2.1 使用框提示生成掩膜；以猫的主体区域裁剪 RGB 图，交给新训练的 YOLO26 分类模型。保留未遮盖的颜色与毛纹。掩膜用于主体裁剪与轮廓展示，不预设它一定提高分类准确率。检测不到或分割失败均单独记录；分割失败时可用检测框裁剪并注明实际路径。

大模型路线：Qwen3-VL-4B-Instruct 在本机以 BF16/SDPA 推理，独立读取原图与固定任务提示，返回猫是否存在、一个品种、可见外观特征。用 Transformers SDK 实际传入图像；以 FastAPI 提供本地图片调用接口，保留请求、返回与配置。无需付费云端 API。

OpenCV/Pillow 负责读取、缩放、裁剪、坐标换算和叠加。显存采用阶段性加载与释放，训练、批量传统推理、批量大模型推理分别执行，避免同时挤占显存。

## 数据与比较

从原始 Oxford-IIIT Pet 标注重新建立清单。官方 trainval 中的猫分出训练和验证，官方 test 保持独立。按 SHA256 检查跨集合重复；所有生成视图继承来源图的集合。训练和阈值／提示调整只看训练与验证。

在任何测试预测前固定每种品种10张的共同测试子集，共120张；两条路线都运行这一清单。传统模型另可评价全部猫测试图片，报告时区分全量与共同子集。比较 Top-1 正确率、宏平均 F1、各类结果、失败、耗时和具体分歧。分割可借数据集 trimap 单独评价，但测试标注不参与推理或自动提示生成。程序不把单图模型分数称为测试准确率。

## 交付

独立 Git 开发历史、可恢复环境、源码、模型获取与启动说明、实际训练／预测记录、项目说明及真实运行录像。本项目自训练分类权重约11MB，随源码提交，使接收者无需重新训练；官方通用权重和原始数据通过完整保留包或下载脚本恢复。外部资源目录可配置，无私人绝对路径依赖。文档按 humanizer-zh 整理，只写真实结果与经历。

界面与服务只监听本机；输入大小有限制，图片先解码；模型返回按字段验证。不执行模型返回中的代码。仓库上传和提交收件人沿用用户此前安排，本轮先完成本地项目。
