# 看图识猫：第三阶段运行说明

项目沿用第二阶段的两条独立路线，不需要重新训练。传统视觉使用YOLO、SAM和两个Swin分类器；本地Qwen负责品种判断、原图观察和图片问答。第三阶段增加用户登录、数据库历史、任务队列，以及Linux上的Docker部署。

## 环境

- Ubuntu 24.04，或Windows上的WSL2 Ubuntu 24.04。
- NVIDIA显卡；现有模型在16GB显存上运行过。Windows/WSL使用已有Windows显卡驱动，不另装Linux显卡内核驱动。
- Docker Engine、Compose插件、NVIDIA Container Toolkit。
- Python 3.12、CUDA 12.8、PyTorch 2.9.1由工作端镜像安装。宿主机不用复制Windows虚拟环境。

普通无GPU的免费小主机无法按当前CUDA配置运行完整模型。开发和本机演示使用现有电脑，不需要付费云账号。PDF没有指定云厂商；以后迁移到其他Linux服务器时，可以继续使用同一套Docker配置。

## 首次运行

在Linux终端进入源码根目录。如果Docker和NVIDIA容器运行时还没装，Ubuntu可使用下面的宿主机安装脚本；安装需要管理员权限，脚本使用Docker和NVIDIA官方软件源：

```bash
sudo bash scripts/install_linux_host.sh
```

先恢复模型。`weights`中要有`yolo26n.pt`、`sam2.1_t.pt`、两个Swin权重、`qwen3-vl-4b`底座目录和`qwen-cat-lora-v4`适配器目录。自训练权重随Git提交；官方大模型可从第二阶段完整保留包恢复，或运行已有的`scripts/download_models.py --only all`。原始训练图片不用上传到运行服务器。

```bash
python3 scripts/setup_stage3.py
bash scripts/start_stage3.sh --build
docker compose logs -f worker
```

初始化脚本只在`.env`不存在时生成随机数据库密码、队列密码和JWT密钥，不覆盖已有配置。`.env`不入库；示例为`.env.example`。如果模型放在别处，只修改`.env`中的`CATVISION_MODEL_ROOT`，其他源码不需要改路径。

浏览器打开`http://127.0.0.1:8080`。首次使用在网页注册自己的应用账号；这不是云平台账号。等页面显示模型就绪后上传照片。登录后可以查看自己的历史照片、修改记录名称、从列表移除已结束记录，并对已识别图片继续提问。

后续启动已有镜像：

```bash
bash scripts/start_stage3.sh
```

默认只监听本机。迁移到远程Linux服务器并确需外部访问时，在`.env`配置`BIND_ADDRESS=0.0.0.0`及实际端口，按部署环境配置入口和HTTPS。

## 服务与数据

nginx是统一网页入口；Streamlit只负责操作界面；FastAPI处理认证和任务接口；SQLAlchemy将用户、任务与结果写入PostgreSQL；RabbitMQ接收图片任务；只有一个GPU工作端加载模型。

同一任务内部A/B并发，不同任务通过队列排队。队列持久化，投递确认，消费端手动确认并预取一条任务。重复的已完成消息不会再次推理；结果先写入文件和数据库再确认消息。工作端崩溃后，原运行中任务标为中断，用户手动重新提交。

数据库和RabbitMQ使用命名卷；图片、问答结果和模型日志放在`runtime/stage3`。从历史列表移除是软删除，原文件保留。普通更新和重建镜像不会删除这些数据。

```bash
docker compose ps
docker compose logs --tail=100 api worker
docker compose stop
docker compose start
```

`docker compose down`会移除容器和项目网络；加`-v`还会删除数据库和消息队列卷，不能把它当作日常停止命令。

## 失败后处理

工作端失败会保存错误堆栈，并停止进程，不自动重试模型或重启容器。先查看`docker compose logs worker`和`runtime/stage3/model-logs`，排除问题后再操作：

```bash
docker compose run --rm worker python scripts/recover_stage3_worker.py
# 确认看过错误日志后：
docker compose run --rm worker python scripts/recover_stage3_worker.py --acknowledge
docker compose up -d worker
```

已经失败或中断的任务仍保留在历史中，网页中的“重新提交”会创建新记录，保留原来的失败过程。

## 接口和提交

入口`/docs`可查看FastAPI交互文档。注册、登录之外的任务与图片接口需要Bearer JWT，用户只能访问自己的记录。

源码仓库包含依赖说明、Dockerfile、Compose、配置示例和真实Git开发历史。部署方可在服务器构建镜像，也可使用`docker save`导出、`docker load`导入已构建镜像，无需上传Docker Hub。部署运行包使用镜像时，源码仓库仍需保留完整代码。

验收视频应展示Linux/Docker启动，以及真实上传图片后A/B结果和图片问答。整批测试准确率写在项目材料中，单图页面只显示这张图的实际输出与耗时。
