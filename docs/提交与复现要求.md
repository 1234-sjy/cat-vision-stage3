# 提交与复现要求

本项目的代码、依赖版本、模型获取方式、运行步骤与真实开发提交统一放在Git仓库中。当前项目介绍和个人感悟是`项目介绍与个人感悟.docx`，旧排版报告在`history`中保留。

## 保留真实开发历史

交接文件使用Git bundle，包含整个仓库的现有提交、作者、时间和父子关系。另一台电脑用`git clone <bundle路径> cat-vision-stage2`恢复，再整体推送到GitHub。普通源码ZIP或网页拖拽上传不能带出这些Git历史。

不要重新`git init`、压成一个提交、倒填日期或为了显示提交次数而制造空提交。后续有实际修改时再正常提交和推送。本地开发提交时间与GitHub收到推送的时间是两个记录，现有材料不冒充此前已经持续在线推送。

## 代码和依赖统一入库

- `catvision`、`scripts`和`web`：模型调用、训练、评估与网页代码。
- `requirements.txt`、`requirements-lock.txt`：依赖与可恢复版本。
- `安装环境.cmd`、`启动项目.cmd`及`scripts/setup.ps1`、`scripts/start.ps1`：环境恢复与启动。
- `weights/breed-swin-v2-fp16.pt`、`configs/active-classifier.json`：本项目训练的当前分类权重与配置。
- `docs/模型来源与训练范围.txt`和下载脚本：官方模型来源、获取和校验方法。
- `artifacts`：实际训练、验证、测试及逐图输出记录。

大型官方模型和原始数据按原完整保留包恢复，或按README获取；代码仓库保留数据来源、划分和输入摘要。项目从自身目录查找资源，外部数据通过参数指定，不要求接收者具有开发机的用户名和目录。

## 交付

向验收者提交GitHub仓库链接、项目介绍与个人感悟Word文档、实际运行视频。Git bundle上传包用于交给操作另一台电脑的Codex或同学，由其恢复并上传仓库；它不代替最终GitHub链接。
